# 0007: Agentic career research with supervised retrieval

- Status: Accepted
- Date: 2026-10-27

## Context

Semantic top-k retrieval cannot establish an exhaustive project count or guarantee that several skills occur in the same project. Visitors also need narrative explanations, comparisons, and useful alternatives when an exact combination is absent. The application already has structured jobs, projects, and skills, compatible pgvector retrieval, two generation providers, and a cancellable public SSE stream.

## Decision

Add an optional supervisor that coordinates specialist agents as tools. Query Analyzer decides which research to request, reviews results, and hands final composition to Thibault Representative. Database translates a natural-language task into one validated structured query; RAG translates a task into one natural-language evidence search. Independent research calls can run concurrently. The Representative alone streams the public answer and chooses suitable prose, lists, or Markdown tables.

Use a small asynchronous state machine on the existing HTTPX adapters, with native OpenAI Responses and Anthropic Messages tool calling. Keep provider continuation items needed by subsequent tool turns, including reasoning-related state, on the server. Add no orchestration framework, separate agent service, or durable conversation store. This follows the supervisor/subagent approach described by [OpenAI orchestration guidance](https://developers.openai.com/api/docs/guides/agents/orchestration) and [LangChain's subagents pattern](https://docs.langchain.com/oss/python/langchain/multi-agent/subagents); the preference for direct, bounded composition is consistent with [Anthropic's guidance on effective agents](https://www.anthropic.com/research/building-effective-agents).

For explicitly supported GPT-6-family model IDs, request low reasoning effort for native decision/tool calls and agentic final synthesis to reduce latency. Preserve default reasoning settings for other models and the RAG-only answer path. Limit this option to the known supported model allowlist rather than assuming every custom model accepts it; see [OpenAI's reasoning guidance](https://developers.openai.com/api/docs/guides/reasoning).

Compile Database tool arguments into parameterized SQLAlchemy predicates; never execute generated SQL. Support bounded Boolean skill expressions, company, title, project role, text, dates, ongoing status, project kind, and pagination. Skills belong to projects. An AND must hold on one project, and a job matches through a project satisfying the complete predicate. NOT also applies within that project; it does not prove that no other project in the job used a skill. Count the complete matching set independently of the displayed page, using newest start month and ID ordering. Return the applied criteria, resolved skill labels, exact counts, current record text, and full source references.

Keep dates, ongoing status, role, company, linked-job identity, and qualifying project references as structured facts separate from the narrative, so shortening long descriptions does not erase those facts.

Resolve skill terms against the actual vocabulary with case-insensitive literal matching and boundaries for short tokens. Thus AI can match the explicit words in Agentic AI without treating LLMs or RAG as exact aliases. Preserve the original exact branch and label related searches separately; related findings never change an original zero count. The model chooses the semantic interpretation and useful follow-up questions, while the application enforces query structure, literal matching, counts, and allowed source scope. Counts refer to stored records and tags, not an exhaustive assertion about real-world experience.

Keep full result-set references in the current run's server-owned registry. A scoped RAG request uses the complete matching set, including records outside the displayed page. Apply composite source-type/record-ID restrictions before semantic and lexical ranking and neighborhood expansion. An empty scope yields no evidence; it never becomes an unrestricted search. Agentic RAG uses current published source revisions with compatible embeddings. Current structured evidence remains usable without embeddings. The disabled RAG-only path retains ADR 0006 behavior, including previous compatible generations during replacement ingestion.

Limit each run to four supervisor decisions and eight research operations, counting specialist repair attempts. Each specialist gets at most one repair attempt for invalid tool arguments. Prevent identical repeated searches and bound tool inputs and evidence. Set one 120-second deadline: research can take up to 90 seconds, and final composition receives at least the reserved 30 seconds plus unused research time. Research failures and exhausted budgets become explicit limitations for the Representative; only already verified evidence may support the answer. A failed query is unknown, not zero. If composition is interrupted, emit an error rather than a successful completion. Release synchronous database sessions before provider calls, and cancel pending asynchronous work when the client disconnects.

Store a defaulted `agents` section in the existing JSON settings record. It contains the mode switch and four role prompts, each with an optional provider/model/token override. An absent override inherits the chat generation settings; the RAG-only chat prompt remains separate. Fixed behavior rules are appended to editable agent prompts. Editing a prompt does not grant tools, change SQL permissions, bypass schema validation, or permit access to an invented result set. Authenticated settings endpoints expose defaults and role capability tests; the three research roles test native tool calling and the Representative tests text generation. Saving settings does not make provider calls. Existing configurations default to disabled without a migration; the approved production rollout enables agentic mode after validation.

Extend the existing SSE contract with `status` events containing a stage and short public message. Emit messages from real execution transitions and results, including separately labeled related searches. Do not expose provider reasoning, raw tool payloads, prompts, keys, or SQL. Preserve `delta`, `done`, and `error`, with exactly one terminal event. Render answers through the Markdown renderer with tables and lists, excluding raw HTML and images and allowing only HTTP(S) links.

Keep conversations in browser memory and retain the existing bounded completed-turn history request. Progress messages are not conversation history. Follow-up filters and offsets are reconstructed from recent exchanges and rechecked against current data; previous assistant replies remain navigation context, never factual evidence. Clarify when relevant context is absent or ambiguous. There is no server conversation database or durable cursor, and edits between questions can change page membership.

## Consequences

Exact filtering and counting are now distinct from semantic ranking, while both contribute to the final answer. Prompt and mode changes apply to the next question without migration or re-ingestion. Disabling agentic mode restores the existing RAG-only pipeline.

Agentic answers can require more provider calls and take longer. Bounded execution and early completion limit this cost; logged role/provider/model and token usage support operational review without logging source bodies or questions. Metadata quality and model interpretation still determine the usefulness of exact and related branches. Current-only agentic semantic retrieval can temporarily omit edited records awaiting ingestion, while their structured data remains available.

Validation covers Boolean combinations within a project, distinct counts and pagination, literal skill resolution, current record reads without embeddings, scoped ranking and freshness, exact versus related results, provider tool continuations, settings inheritance and capability tests, cancellation and terminal events, and browser activity and Markdown rendering. The normal isolated validation suite remains required before deployment. The existing Docker Compose deployment and database volume remain in place; this feature introduces no infrastructure service.

Ship a read-only evaluator and fixed query fixtures in the API runtime image to compare agentic and RAG-only answers with the saved models. It changes mode only in memory and emits JSONL with answers, latency, activity, and structured oracle comparisons. Counts, full membership, and pages can be checked automatically; semantic filter interpretation and narrative quality still require human review. Evaluations make billable provider calls. Reported model usage covers agent tool decisions and excludes streamed answers, embeddings, and reranking, so it cannot establish total cost.
